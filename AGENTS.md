# Kinwin Codex Instructions

* Work only on the explicitly assigned task.
* Build and review one screen, flow, or technical package at a time.
* Do not silently change approved product decisions.
* Do not access or reuse the previous Kinwin web application.
* Use mock data and local state until real integrations are explicitly requested.
* Preserve existing working behavior.
* Avoid speculative abstractions and unnecessary dependencies.
* Never put secret keys in mobile client code.
* Run relevant validation after changes.
* Explain results and unavoidable founder actions in clear, beginner-friendly Swedish.

Read `docs/PRODUCT_DECISIONS.md` when a task affects product behavior, UX, copy, business logic, or architecture.

Do not assume Claude Code has modified the repository unless the founder explicitly says so or Git history shows it.

Read `docs/AI_HANDOFF.md` before planning new work, and follow `docs/AI_WORKFLOW.md`'s rule for updating it before reporting a task complete.
